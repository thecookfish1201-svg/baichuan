# 提示词组装规范

> 阶段二建立。任何模块需要拼提示词，必须走 `PromptAssembler`，不允许各功能自行拼接。

## 1. 分层顺序（固定）

```
[system]
  系统提示词（agent.systemPrompt）
  人设（agent.persona）
[memory]        ← 阶段三：长期记忆摘要
[summary]       ← 阶段三：上下文压缩摘要
[history]       ← 当前分支消息（按 createdAt 升序）
   user / assistant 交替
```

- 没有内容的层直接省略，不输出空 system 消息。
- 记忆与压缩摘要必须以「独立分层」插入，不得拼进系统提示词正文。
- 消息时间只存在于数据库元数据，**不进入提示词**，避免破坏上下文缓存前缀。

## 2. 分支路径选择

- 会话表 `conversations.activeLeafMessageId` 记录当前路径末端。
- 从末端沿 `messages.parentId` 回溯到根，得到当前分支的完整消息列表。
- 生成新回复时，上下文取「父消息」回溯路径，不包含正在生成的空占位消息。
- `siblingSeq` 只用于同一父节点下兄弟消息的稳定排序，不进入提示词。

## 3. 参数传递

- 温度、推理深度、流式开关：`agents.generationJson`（JSON），由适配层转换。
- 不同供应商不支持的参数由适配层丢弃或映射，聊天核心不感知。
- `temperature` 默认 0.7；`max_tokens` 默认不传（交给服务端默认）。

## 4. 错误与重试

- 失败时保留已生成的部分内容，状态置为 `failed`，错误摘要写入 `messages.errorSummary`（脱敏）。
- 阶段三将错误摘要迁移到独立 `error_events` 表，消息只保留 `errorId`。
- 不做自动无限重试；401/余额不足等错误直接提示用户。

## 5. 后续扩展点（阶段三占位）

| 能力 | 插入位置 | 说明 |
|---|---|---|
| 记忆 | system 与 history 之间 | 取该智能体 top-K 记忆，压缩为一段 |
| 上下文压缩 | 记忆之后 | 超过阈值时用辅助模型生成摘要，保留 `up_to_message_id` |
| 搜索来源 | assistant 消息之后 | 引用以独立结构保存，不拼进正文 |
| 工具调用 | 适配层 | OpenAI 兼容的 tools 字段，阶段五接入 |
