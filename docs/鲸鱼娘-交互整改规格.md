## 1. 错误展示规格

### 1.1 两类错误，两个出口

| 类型 | 例子 | 出口 | 是否打断阅读 |
|---|---|---|---|
| 操作级 / 全局错误 | 未配置模型、搜索未配置、网络失败、附件保存失败、消息落库失败、Agent 未授权 | 底部 Snackbar | 不打断，覆盖显示 |
| 消息级错误 | 某条回复生成失败、生成中断 | 消息内联：气泡前红色感叹号 + 气泡下居中灰色提示，详情进「错误记录」 | 内联，跟随消息 |

规则：

1. 同一个错误事件只走一个出口，不允许 Snackbar 与内联条同时报同一件事。
2. 全局错误用 Snackbar，不新增顶部内联条。原因：两套聊天页已有 SnackbarHost；顶部内联条会挤压消息流，流式生成时造成跳动。
3. 消息级内联保留总提示词要求的「微信式红色感叹号 + 居中灰色错误提示」，它是历史消息的一部分，不因一次性错误改用 Snackbar 而消失。

### 1.2 Snackbar 参数

| 项 | 规格 |
|---|---|
| 位置 | 底部，输入区上方 8dp；不遮挡输入框、不遮挡发送键 |
| 宽度 | `fillMaxWidth`，水平外边距 16dp；平板最大宽 560dp 居中 |
| 圆角 | 12dp |
| 内边距 | 水平 12dp / 垂直 10dp |
| 左侧图标 | 16dp；错误用 `Warning`，信息用 `Info`；图标与文字间距 8dp |
| 文字 | 14sp / 20dp 行高；最多 3 行，超出省略 |
| 关闭 | 右侧 `Close` 18dp，热区 48dp；点击立即消失 |
| 时长 | 普通 4 秒；带「重试」动作 6 秒；手动关闭优先 |
| 队列 | 同时只显示 1 条；后续排队，最多 2 条，超出丢弃最旧 |
| 去重 | 同一错误码 5 秒内不重复显示；相同文案不叠加 |
| 出现/消失 | 淡入 120ms，淡出 100ms；不做位移弹跳 |
| 无障碍 | `liveRegion = Polite`，TalkBack 自动朗读一次；关闭按钮有 contentDescription「关闭提示」 |

配色：

| 项 | 浅色 | 深色 |
|---|---|---|
| 背景 | `#2E3138` | `#E8EAEE` |
| 文字 | `#F5F6F8` | `#1A1C20` |
| 错误图标 | `#FF8A8A` | `#D93A3A` |
| 信息图标 | `#8FA8FF` | `#2F5BEA` |
| 关闭图标 | `#C9CCD2` | `#555A63` |
| 动作按钮文字 | `#8FA8FF` | `#2F5BEA` |

说明：Snackbar 使用反色底，和页面明显区分；错误只靠图标与文案表达，不整条铺红，避免在深色下刺眼。

位置实现要点：

- 微信式页面：`Scaffold` 的 `snackbarHost` 位于 `bottomBar` 上方，天然不挡输入栏；确认 `SnackbarHost` 加水平 16dp 内边距。
- DeepSeek 式页面：输入卡在 `Column` 底部、不在 `bottomBar`，`SnackbarHost` 会被输入卡盖住；需把 host 放在消息列表与输入卡之间，或给 host 加与输入卡等高的底部偏移。建议前者：`Box` 内 `LazyColumn` + 底部对齐的 `SnackbarHost`，底部偏移 = 输入卡高度 + 8dp，随 IME 一起上移。

### 1.3 文案格式

统一格式：**发生了什么 + 可以做什么**，两句话，句号结尾。

- 主句（问题）≤ 24 个汉字；操作句（下一步）≤ 20 个汉字；总长 ≤ 44 个汉字。
- 不用感叹号、不用「错误」「失败」连用、不用技术术语、不出现异常类名、堆栈、URL、请求头、API Key 片段。
- 操作句必须给出用户能执行的路径或动作；无法处理时直接说「请稍后重试」。
- 不写「请联系客服」，项目无客服。
- 文案不使用 Emoji。

文案映射表（建议直接采用）：

| 错误码 | 场景 | 文案 | 动作 |
|---|---|---|---|
| `MODEL_MISSING` | 未配置模型 | 还没配置模型。请到「管理 → 模型配置」添加服务商并选择模型。 | 无 |
| `SEARCH_MISSING` | 搜索未配置 | 搜索服务还没配置。请到「我的 → 网络搜索」中设置。 | 无 |
| `AGENT_UNAUTHORIZED` | Agent 未授权 | 这个智能体还没有 Agent 权限。可在智能体设置中授权。 | 无 |
| `NETWORK` | 网络失败 / 超时 | 网络连接失败。检查网络后重试。 | 重试 |
| `AUTH` | 401 / Key 无效 | API Key 无效或已过期。请到模型配置中检查。 | 无 |
| `BALANCE` | 402 / 余额不足 | 账户余额不足。请充值或更换服务商。 | 无 |
| `RATE_LIMIT` | 429 | 请求过于频繁。请稍后再试。 | 无 |
| `SERVER` | 5xx | 服务暂时不可用。请稍后重试。 | 重试 |
| `ATTACHMENT_SAVE` | 附件保存失败 | 附件没能保存。草稿已保留，可重试或移除附件。 | 重试 |
| `MESSAGE_SAVE` | 消息落库失败 | 消息没能保存。草稿已保留，请重试。 | 重试 |
| `CONVERSATION_MISSING` | 会话不存在 | 会话已被删除。请返回消息列表重新进入。 | 无 |
| `GENERATION` | 生成中断 | 生成中断了。可以重新生成或稍后重试。 | 重试 |
| `AGENT_FAILED` | Agent 任务失败 | 智能体任务失败。可在「我的 → Agent 运行记录」查看详情。 | 无 |
| `LINK_UNAVAILABLE` | 无浏览器 | 没有可用的浏览器。链接已复制。 | 无 |
| `CLIPBOARD` | 复制失败 | 复制失败。请长按文本手动选择。 | 无 |

敏感信息处理：

1. ViewModel 里现有 `failGeneration("发送失败：${e.message}")` 与 `globalError = e.message` 属于风险点：`e.message` 可能带数据库路径、URL 查询参数、响应体片段。**UI 层禁止直接显示异常 message**，改映射为固定文案；原始异常只进已脱敏日志。
2. HTTP 错误只显示类别（认证、余额、限流、服务端、网络），不显示响应 JSON 或请求头。
3. 日志与 UI 都不允许出现 `Authorization`、`api_key`、`Bearer`、`?key=` 等片段；验收时在错误文案上做字符串检查。

### 1.4 与现有「居中灰色提示」的关系

| 项 | 消息内联（保留） | Snackbar（新增细节） |
|---|---|---|
| 触发 | 某条消息 `status = failed` | 全局操作失败 |
| 位置 | 该消息气泡下方，居中 | 输入区上方，悬浮 |
| 样式 | 12sp、`#8A8A8A`（深色 `#9AA1AE`）、无底色、单行或两行 | 反色底、14sp、带图标与关闭 |
| 点击 | 可点，进入错误记录 | 关闭即消失 |
| 内容 | 简短：「回复失败，可重新生成」 | 发生了什么 + 可以做什么 |
| 关系 | 历史可追溯 | 一次性 |

- 不允许把消息级错误再弹一次 Snackbar。
- 不允许把全局错误做成聊天流里的灰色居中条（会随滚动消失，用户可能错过）。
- 错误记录页入口不变；Snackbar 第一版不带「去设置」跳转，文案已给出路径，避免新增跨页导航依赖。只有「重试」动作可调用当前页已有能力（`send` / `regenerate`）。

### 1.5 实现约定（供开发落地）

1. 把 `globalError: String?` 升级为一次性事件：`ErrorEvent(id: Long, code: ErrorCode, message: String, retryable: Boolean)`；`id` 单调递增。
2. UI 用 `LaunchedEffect(event?.id)` 显示，显示后调用 `consumeError(event.id)`；旋转、重组、返回前台不重放已消费事件。
3. `showSnackbar` 是挂起函数，必须放在 `LaunchedEffect` 内；不要 `launch` 多条并行，避免排队错乱。
4. Snackbar 的「关闭」调用 `SnackbarHostState.currentSnackbarData?.dismiss()`。
5. 测试断言：同一错误连续触发两次，5 秒内只出现一次；旋转屏幕后不再出现。

## 2. 空操作入口处理规格

### 2.1 判定规则（按顺序套用）

| 条件 | 处理 | 理由 |
|---|---|---|
| 目标页面已存在且可用 | 接上 `onClick` | 不留空回调 |
| 目标页面存在，但当前条件不足（未配置模型、无权限） | 保留入口并跳转，由目标页显示空状态与配置指引 | 入口本身不是空操作 |
| 功能未实现，且不影响用户完成主流程 | **隐藏**（首选） | 最干净，避免承诺 |
| 功能未实现，但需要让用户知道后续会有 | **禁用 + 「规划中」标签**，无箭头、无点击反馈 | 诚实但不误导 |
| 功能未实现，但用户点了必须解释 | 禁用 + 副标题写明原因 | 不用「敬请期待」Toast |

禁止：

- 空回调 `onClick = {}` 配箭头。
- 可点击但弹「敬请期待」「将在阶段三接入」这类空承诺 Toast。
- 用 40% 透明图标假装禁用却仍可点。

### 2.2 逐项处置

| 入口 | 现状 | 处置 | 说明 |
|---|---|---|---|
| 消息页搜索 | 图标已不存在，import 残留 | 保持隐藏，删除 `Search` 等未使用 import | 搜索未实现前不放入口；实现后再加 24dp 图标 |
| 消息页新建智能体 | 空状态有按钮；列表非空时无 `+` | 保留空状态按钮；列表态可在顶栏加 `Add`（已有 `onCreateAgent`） | 属功能补齐，非本轮必做 |
| 管理 → 黑名单 | 无回调、有箭头 | 隐藏 | 页面未实现，隐藏最干净 |
| 管理 → 权限记录 | 无回调、有箭头 | 隐藏，或合并进「Agent 运行记录」 | 不建议本轮新做页面 |
| 管理 → 添加服务商/模型配置 | 已接 `onOpenModelConfig` | 保留 | — |
| 我的 → 模型、存储与通用设置 | 无回调、有箭头 | 接 `onOpenModelConfig`（或新建设置聚合页） | 已有目标页，属「应接通」而非隐藏 |
| 我的 → 关于 | 无回调、有箭头 | 做轻量 `AboutDialog`（版本、开源协议、项目地址）；不做则禁用 + 规划中 | 对话框成本低，建议做 |
| 我的 → 其他行 | 已接 | 保留 | — |
| 消息长按「朗读」 | 有入口，TTS 已具备基础能力 | 保留，未配置 TTS 时走系统 TTS；彻底不可用则隐藏 | 不显示无效入口 |

### 2.3 「规划中」标签视觉

- 位置：行尾，替代箭头。
- 文字：「规划中」三个字，11sp / 15dp，Regular。
- 颜色：`#8A8A8A`（浅）/ `#9AA1AE`（深）；标签本身不加背景、不加边框，保持素净。
- 行状态：整行 `enabled = false`；标题与图标降到 60% 不透明度；无 ripple；不响应点击。
- 无障碍：`semantics { disabled() }`，TalkBack 读「黑名单，已停用」；不要只靠颜色表达。
- 行高保持 64dp，分割线保留。

### 2.4 空状态文案

- 消息页空状态：「还没有智能体。创建一个，开始对话。」按钮「创建智能体」。
- 发现页空状态：「插件还在路上。这里将显示已安装与可获取的插件。」不放假入口。
- 搜索无结果：「没有找到匹配的内容。换个关键词试试。」
- 错误记录空：「没有错误记录。」不写「一切正常」这类营销句。

## 3. ListRow 交互 API

### 3.1 问题

```kotlin
onClick: () -> Unit = {},   // 默认空操作
showArrow: Boolean = true,  // 默认伪装成导航入口
```

17 处调用点里，凡是没传 `onClick` 的都会变成「有箭头、点了没反应」。必须在类型层面消除这种可能。

### 3.2 建议 API（单组件，不新增第二套样式）

```kotlin
enum class ListRowStatus { Planned, Unavailable }

@Composable
fun ListRow(
    icon: ImageVector,
    title: String,
    modifier: Modifier = Modifier,
    subtitle: String? = null,
    onClick: (() -> Unit)? = null,
    enabled: Boolean = onClick != null,
    status: ListRowStatus? = null,
    showDivider: Boolean = true,
    iconTint: Color = Color.Unspecified,
    trailing: (@Composable () -> Unit)? = null,
)
```

规则：

1. `onClick` 默认为 `null`，**没有默认空 lambda**；调用方必须显式给函数或 `null`。
2. `enabled` 由 `onClick` 推导；显式传 `enabled = false` 时即使有 `onClick` 也不响应。
3. `showArrow` 不再作为外部参数，内部规则：可点击才显示箭头；禁用/规划中不显示。
4. `trailing` 用于「规划中」标签、版本号、开关等；默认不渲染任何尾部元素。
5. 可点击行必须提供 `onClickLabel`（默认「打开」），TalkBack 能读出动作。

三种用法：

| 用法 | 写法 | 视觉 |
|---|---|---|
| 可点击 | `ListRow(..., onClick = { nav(...) })` | 标题主色、图标 100%、右侧 `KeyboardArrowRight` 20dp、ripple、按下背景 `surfaceVariant` 8% |
| 禁用（规划中） | `ListRow(..., enabled = false, status = Planned)` | 标题/图标 60%、无箭头、尾部「规划中」11sp 灰、无 ripple、不可聚焦 |
| 禁用（有原因） | `ListRow(..., enabled = false, subtitle = "需要先配置模型")` | 副标题说明原因，其余同上，可保留无箭头 |

### 3.3 尺寸与配色

| 项 | 规格 |
|---|---|
| 最小行高 | 64dp（双行）/ 56dp（单行）；随字号放大自适应 |
| 水平内边距 | 16dp |
| 图标 | 22dp，与文字间距 14dp；颜色 `onSurfaceVariant` |
| 标题 | 16sp / 22dp；可点击时 `onSurface`，禁用时 60% |
| 副标题 | 13sp / 18dp；`onSurfaceVariant` |
| 箭头 | 20dp，`onSurfaceVariant` 60% |
| 分割线 | 0.5dp，左缩进 52dp（16 + 22 + 14）；与现有实现一致 |
| 按压反馈 | ripple 默认；禁用行无 ripple |

### 3.4 迁移步骤

1. 改 `ListRow` 签名，删除 `showArrow` 默认参数与空 lambda。
2. `grep -rn "ListRow("` 逐处处理 17 个调用点：有目标页的补 `onClick`；没有的显式 `enabled = false` + `status = Planned` 或直接删行。
3. 删除所有「有箭头但无回调」的行，验收时逐屏点击检查。
4. 保留 `ListRow` 单一样式，不新增 `DisabledListRow`，避免两套视觉漂移。

### 3.5 禁止事项

- 禁止用 `Modifier.clickable {}` 包一层空回调绕过。
- 禁止用 `alpha = 0.5f` 伪装禁用但仍可点击。
- 禁止把「规划中」做成可点击后弹 Toast。
- 禁止在有回调的行上关闭箭头又保留点击（会少一个导航暗示）。

## 4. C 风格操作对齐

### 4.1 原则

C 风格（DeepSeek 式）要保持「正文无壳、留白大、控件少」。补操作不等于把 A 风格的按钮搬过来：

- 用户消息不显示常驻操作栏，只提供长按菜单。
- AI 回复保留一条极简操作栏，最多 3 个入口，其余收进「更多」。
- 不使用「‹ 1/2 ›」浮层；分支切换进长按菜单。
- 所有菜单项文字与 A 风格一致，避免同一功能两种叫法。

### 4.2 长按菜单

| 消息 | 菜单项（顺序） | 图标（core 可用） | 说明 |
|---|---|---|---|
| 用户消息 | 复制 | 无图标（文字项） | 复制原文 |
| | 编辑并重发 | `Edit` | 打开编辑弹窗，确认后生成新分支 |
| | 删除 | `Delete`（error 色） | 二次确认 |
| AI 消息 | 复制 | 无图标 | 复制 Markdown 原文 |
| | 重新生成 | `Refresh` | 生成新分支 |
| | 上一条版本 / 下一条版本 | `KeyboardArrowLeft` / `KeyboardArrowRight` | 仅 `branchInfo` 存在时显示 |
| | 分享 | `Share` | 系统分享纯文本 |
| | 朗读 | `PlayArrow` | TTS 不可用时隐藏 |
| | 删除 | `Delete`（error 色） | 二次确认 |

菜单规格：

- 使用 `DropdownMenu`，锚定在消息气泡/正文上；不遮挡输入区。
- 菜单背景 `surface`，圆角 12dp，阴影 2dp，宽度 200–240dp。
- 菜单项高 48dp，水平内边距 12dp，图标 20dp，图标文字间距 12dp，文字 15sp。
- 危险项文字与图标用 `colorScheme.error`；不放在第一项。
- 菜单展开时消息行不变形；点击外部关闭。
- 长按手势：`combinedClickable(onClick = {}, onLongClick = ...)`，`onLongClickLabel = "更多操作"`；TalkBack 用户可通过操作菜单触发长按。

### 4.3 AI 操作栏（保持极简）

| 方案 | 内容 | 适用 |
|---|---|---|
| 推荐 | `Refresh`（重新生成）+ `MoreVert`（更多）；复制、分享、删除、分支进「更多」菜单 | 最贴近官方，控件最少 |
| 备选 | 文字「复制」+ `Refresh` + `MoreVert` | 复制可达性更高 |

- 图标 22dp，热区 48×48dp，右对齐；左侧不留空白。
- 与正文间距 8dp；与下一条消息间距 16dp。
- 生成中隐藏操作栏，显示「停止生成」；生成完成后淡入。
- 朗读不放在操作栏，避免未配置 TTS 时出现死按钮。
- 点赞/点踩第一版不做：`material-icons-core` 无 `ThumbDown`，混用文字「没用」会破坏极简；等赞踩状态能持久化后再加。

### 4.4 删除确认

删除是不可逆的数据操作，必须二次确认：

- 弹窗标题：「删除这条消息？」
- 正文：「删除后将从对话中移除，界面不提供恢复。同一分支中的其他回复会保留。」
- 确认按钮：「删除」（`colorScheme.error`，放在右侧）；取消按钮：「取消」。
- 默认焦点在「取消」；返回键等同取消。
- 删除后 Snackbar：「消息已删除。」不带「撤销」（数据库软删除可恢复，但第一版不暴露撤销，避免半成品）。
- 如果该消息是当前分支唯一叶子，删除后回到上一条；若会话为空，显示空状态。
- 连续删除时每次确认，不做「不再提示」。

### 4.5 分支切换

- 入口：AI 消息长按菜单「上一条版本」「下一条版本」，或「更多」菜单。
- 仅当 `branchInfo.total > 1` 时显示；单分支不显示禁用项。
- 切换后保持滚动位置在当前消息，不跳到顶部。
- 菜单文字带序号：「上一条版本（1/2）」「下一条版本（2/2）」；序号用 `branchInfo.index/total`。
- A 风格保留现有 `‹ 1/2 ›` 切换器，但按第 6 章扩到 48dp 热区；C 风格不显示该浮层。

### 4.6 与 A 风格的一致性

| 功能 | A 风格 | C 风格 |
|---|---|---|
| 编辑并重发 | 长按用户消息 → 编辑并重发 | 长按用户消息 → 编辑并重发 |
| 重新生成 | 长按 AI 消息 → 重新生成 | 操作栏 `Refresh` + 长按菜单 |
| 删除 | 长按菜单 + 确认弹窗 | 长按菜单 + 确认弹窗 |
| 分支 | 气泡下 `‹ 1/2 ›`（48dp 热区） | 长按菜单文字项 |
| 复制 | 长按菜单 / 操作栏 | 长按菜单 / 更多菜单 |
| 朗读 | 长按菜单（可用时） | 长按菜单（可用时） |

菜单文案统一：复制、编辑并重发、重新生成、上一条版本、下一条版本、分享、朗读、删除。禁止「重发」「再生成」「删掉」等变体。

## 5. 输入框文案

### 5.1 结论

ASR 未接入前，两套聊天页统一使用：

- 占位文字：**「发消息」**（当前实现已正确，保持不变）。
- 禁止：「发消息或按住说话」「按住说话」「长按说话」——界面没有语音入口时，这句话是错误承诺。
- 语音按钮：不显示；不为了文案放一个无效麦克风。
- 附件按钮保留 `Add`，contentDescription「添加附件」。

### 5.2 细节

| 项 | 规格 |
|---|---|
| 字号 | 16sp（A）/ 17sp（C），`onSurfaceVariant` 60% |
| 行数 | 输入框内仅显示占位第一行；多行输入时占位上移 |
| 附件选择后 | 占位不变，附件条显示在输入框上方 |
| 键盘动作 | `ImeAction.Send`；空输入时回车不发送 |
| 硬件键盘 | Enter 发送，Shift+Enter 换行 |
| 输入法组合态 | 组合中不发送，不截断候选 |
| 多语言 | 英文界面用「Message」；不出现「Type a message or hold to talk」 |

### 5.3 将来接入 ASR 时

必须同时满足三件事，才可以改文案：

1. 输入框左侧出现麦克风按钮（`mic` 图标不可用，core 无；可用 `PlayArrow` 之外的方案或项目自绘 24dp 矢量）。
2. 文案改为「发消息或按住说话」。
3. 长按录音、松开发送、上滑取消的提示可见。

在三个条件没有同时满足前，保持「发消息」。

## 6. 触控与无障碍

### 6.1 48dp 清单

| 元素 | 当前 | 目标 |
|---|---|---|
| 附件移除按钮 | 22dp / 24dp 的 `IconButton`（被 `size()` 覆盖） | 视觉 18dp 图标，热区 48×48dp |
| 分支切换左/右 | 文字 `‹` `›` + padding 6/2，约 30×20dp | 各 48×48dp `IconButton`，图标 20dp |
| 分支状态文字 | 不可点 | 只读文本，自身不设点击 |
| 来源折叠行 | Row 点击，行高约 20dp | 整行最小高 48dp，整行可点 |
| 来源链接项 | `bodySmall` + 上下 4dp，行高约 21dp | 每项最小高 48dp，整行可点 |
| 操作栏按钮 | `TextButton` 默认约 40dp | 最小高 48dp |
| 发送 / 停止 | IconButton 默认 48dp（保留） | 48dp，不缩小 |
| 顶栏图标 | IconButton 默认 48dp | 保持 |
| 菜单项 | `DropdownMenuItem` 48dp | 保持；字号放大后自适应增高 |
| 附件添加 | IconButton 48dp | 保持 |

实现约束：

- 不要用 `Modifier.size(24.dp)` 直接套在 `IconButton` 上——它会同时缩小热区。需要小图标时，`Icon` 设 18–20dp，`IconButton` 保持 48dp。
- 列表行内的删除按钮可用 40dp 视觉容器 + 48dp `minimumInteractiveComponentSize()`，但相邻元素之间要留 8dp，避免热区重叠。
- 所有可点区域的最小尺寸用 `Modifier.minimumInteractiveComponentSize()` 兜底（字体放大时仍有效）。

### 6.2 contentDescription 文案

| 元素 | contentDescription |
|---|---|
| 附件移除 | 移除附件：报告.pdf |
| 分支左 | 上一条分支 |
| 分支右 | 下一条分支 |
| 分支状态 | 第 1 条，共 2 条 |
| 来源折叠（收起时） | 展开搜索来源，共 3 条 |
| 来源折叠（展开时） | 收起搜索来源 |
| 来源链接 | 打开来源：标题（将在浏览器打开） |
| 复制 | 复制这条回复 |
| 重新生成 | 重新生成这条回复 |
| 更多 | 更多操作 |
| 删除 | 删除这条消息 |
| 发送 | 发送 |
| 停止 | 停止生成 |
| 添加附件 | 添加附件 |
| 关闭提示 | 关闭提示 |
| 主题切换 | 外观设置 |
| 规划中行 | 由 `enabled = false` 触发的「已停用」由系统朗读，不重复写 |

规则：

- 图标按钮必须给 contentDescription；纯装饰图标（如行尾箭头、时间轴圆点）置 `null`。
- 文案不带句号、不带标点堆叠；动词开头。
- 名称动态拼接时截断到 20 字，避免 TalkBack 朗读过长。
- 同一屏不出现两个相同 description 的可点元素；来源链接用标题区分。

### 6.3 长按菜单的无障碍

- 消息气泡：`combinedClickable(onClick = {}, onLongClick = { menu = true }, onLongClickLabel = "更多操作")`。
- TalkBack 用户无法可靠执行长按，需要 `CustomAccessibilityAction("更多操作") { menu = true; true }`。
- 菜单展开后焦点进入菜单第一项；关闭后焦点回到触发消息。
- 删除确认弹窗打开时，焦点移到标题，朗读完整提示；确认按钮不默认聚焦。

### 6.4 对比度与字体

- 正文与背景 ≥ 4.5:1；大号标题 ≥ 3:1。
- 禁用文字 ≥ 3:1；「规划中」标签 ≥ 4.5:1，不能淡到看不见。
- Snackbar 文字与反色底 ≥ 4.5:1。
- 系统字号放大 1.3 倍：行高自适应，菜单项不截断，输入框不挤出屏幕。
- 不用纯色块 + 文字作为唯一状态表达；错误同时有图标与文案。

### 6.5 来源与链接

- 展开来源后，每条链接行高 48dp，标题单行省略，右侧无箭头（避免与导航混淆）。
- 点击打开系统浏览器；无浏览器时 Snackbar「没有可用的浏览器。链接已复制。」，并把 URL 写入剪贴板。
- 链接 `role` 使用 `Role.Button`，description 明确「将在浏览器打开」。
- 来源 JSON 解析失败时整块隐藏，不显示空的白条。

## 8. 与任务单其他项的关系与风险提示

1. **状态机双源**：`ChatUiState` 仍同时有 `isStreaming` 与 `composerState`。C 风格当前用 `isStreaming` 判断发送/停止，A 风格用 `composerState`；PREPARING 阶段两者不一致时会短暂出现「可发送」。属代码实现范围，建议统一以 `composerState` 为唯一事实源，`isStreaming` 只作为派生值（`state == STREAMING`）。
2. **C 风格重复实现**：`ChatScreen` 内仍保留 `deepSeekStyle` 分支与旧的「阶段三接入」胶囊 Toast，但 style 为 deepseek 时已提前 return 到 `DeepSeekChat`，这段是死代码。建议删除，避免以后误改错分支。
3. **DS 用户气泡色**：当前 `DSUserBubbleLight = #F2F3F5`、`DSUserBubbleDark = #26282C`，与《视觉规范-DeepSeek风格.md》的 `#E8EEFB` / `#2A2A2A` 不一致；本轮不强制改，但建议随 C 风格整改一起对齐。
4. **删除是软删除**：数据库有 `deleted_at`，确认弹窗文案不要写「永久删除」；写「删除后将从对话中移除，界面不提供恢复」是指界面不提供撤销，不是物理删除。两者口径要统一。
5. **消息级错误详情**：错误记录页已存在，但聊天页到错误记录没有导航回调。本轮先不做跳转，文案写清路径即可；后续再加。
6. **C 风格消息错误缺少红色感叹号**：微信式当前在失败气泡前有 `ic_error_circle` 18dp，C 风格只有气泡下方的居中文字。本轮应给 C 补同款 18dp 红色感叹号（用现有 `ic_error_circle` 或 core 的 `Warning`），与主规范一致。
