## 批次 1：数据安全

### 插件 ZIP（`core/plugin/PluginManager.kt`）

已完成：
- 插件 ID 白名单（小写字母/数字/点/下划线/连字符，拒绝 `..`）
- entry 路径校验：绝对路径、反斜杠、NUL、控制字符、`..`、空段
- 资源限制：条目 ≤100、单文件 ≤4MB、总解压 ≤8MB、路径 ≤200
- staging 安装 + 旧目录 rename 备份 + 失败回滚
- manifest 校验：名称/版本/API 版本格式、权限字符集与重复、依赖 ID

遗留：
- 未做文件类型白名单（任意扩展名仍可落盘）
- 文件替换与数据库更新的补偿逻辑仍不完整（DB 失败时回滚文件，但极端情况下可能不一致）

### 备份（`core/backup/BackupManager.kt`）

已完成：
- readZip 限制：条目 ≤500、单文件 ≤32MB、总解压 ≤256MB、路径校验、重复路径拒绝
- verify 双向校验：manifest.files 与 archive entries 完全相等，类别白名单、路径白名单、SHA 格式、大小校验
- 快照强制：快照失败直接中止导入，不再吞异常
- 快照包含附件二进制（`snapshotToBytes` 读取 attachments 表引用的文件）
- 恢复附件时 canonical containment 校验；attachments.json 中 uri 恢复前校验
- 备份类别新增 Agent（授权/运行/调用记录）、插件、MCP

遗留：
- 导入未采用完整状态机（SELECTED→…→COMMITTED），失败回滚依赖快照
- 附件写入仍在数据库事务之外（staging 方案未实现）
- 文件夹备份路径校验未同步加强（`readFolderEntries`）

### 附件读取（`core/media/AttachmentStore.kt`）

已完成：`resolve()` 边界校验，`fileOf`/`readBase64` 只能读取 `files/attachments/` 下的文件，阻止恢复的恶意路径读取数据库等私有文件。

### 数据库（`core/AppContainer.kt`、`core/db/BaichuanDatabase.kt`）

已完成：
- 移除启动自动 `deleteDatabase()`
- 移除 `fallbackToDestructiveMigration()`
- 打开失败重试一次后抛出明确异常
- `MainActivity` 启动时捕获失败并显示数据库恢复界面（重试，不删数据）

## 批次 2：Agent 正确性

已完成：
- 移除「授权即全量路由」：改为聊天页显式 Agent 模式开关（授权才显示，默认关闭）
- Agent 任务独立 Job：`stopGenerating()` 同时取消流式与 Agent
- `AgentRunner` 终态保障：取消 → cancelled、异常 → failed、超轮数 → failed
- 每次工具执行前重新读取授权（撤销即时阻断、说明版本变化阻断）
- 工具参数：长度上限 4000、JSON 合法性校验，非法时返回结构化错误并记录
- 上下文传递：`runAgent` 传入当前分支历史消息（不含本次 user 文本）

遗留：
- `AgentActionEntity.confirmed` 仍写死 true（只读工具语义待改）
- 权限等级 A/B 未映射到工具集合（当前工具均为只读）
- 应用重启后 RUNNING 状态扫描标记未实现
- 工具调用总时长/总次数上限仅有轮数（6 轮），单轮调用数未限制
