## 3. 真实缺陷清单

### P0 — 阻塞发布

**P0-1｜`regenerate` / `editAndResend` 不受状态机保护**
- `ChatViewModel.regenerate()` 242-249、`editAndResend()` 251-262 只调用一次 `canStartGeneration()`，随后 `launch`；`generate()` 393-461 只写 `isStreaming`，**不写 `composerState`**。
- 后果：AI 消息点「重新生成」后 `composerState` 仍为 `COMPLETED`，输入区显示发送而不是停止；连点会并发多个请求；流式中无法停止。
- 必测：重新生成连点 3 次 → 只 1 个请求；生成中点停止 → CANCELLED。

**P0-2｜删除消息后上下文路径断裂**
- `MessageDao.listByConversation()` 11-15 排除 `deletedAt`；`ChatRepository.pathTo()` 39-51 沿 `parentId` 回溯，父节点被删则 `byId[it]` 为 null，回溯提前终止，**返回从断点开始的部分路径**，不报错。
- `PromptAssembler.assemble()` 52-62 不校验首条非 system 是否为 user、不检查孤立 assistant/tool。
- 后果：删除 user 消息后继续发送，请求可能以 assistant 开头 → 服务端 `an assistant message must follow a user message`（与用户录屏 00:30-00:36 一致）。
- 必测：删根 user / 删中间 user / 删 assistant / 删当前叶子 / 切到含删除祖先的分支后发送。

**P0-3｜图片-only 消息被丢弃**
- `PromptAssembler.assemble()` 54：`if (message.content.isBlank()) return@forEach`，即使 `imagesByMessage[id]` 有图片也跳过。
- 必测：纯图片、文字+图片、多图片、备份恢复后附件。

**P0-4｜原始 reasoning 展示**
- `ChatScreen.MessageItem` 369-371 传入 `reasoning`；`ReasoningPanel` 682-721 可展开显示原文（录屏 00:09-00:12 的「我们需要回答用户」「根据历史摘要」）。
- 处置：不再展示原文，只保留「思考中…／已思考（用时 N 秒）」；provider 明确 summary 才另做白名单渲染。数据库字段保留不删。

**P0-5｜A 风格正文未渲染 Markdown**
- `ChatScreen` 391-397 直接 `Text(message.content)`；`MarkdownText` 只在 C 页面使用。录屏中 `**粗体标记**` 原样出现。
- 处置：气泡内统一 Markdown renderer；补齐有序列表、引用、链接、代码块横向滚动、流式未闭合标记降级。

**P0-6｜原始错误文本进入 UI**
- `ChatViewModel` 621/629（`globalError = e.message`）、`errorSummary = e.message`；`OpenAiCompatibleAdapter.httpError()` 333-347 的 `else` 分支直接回传服务端 `error.message`。
- 录屏 00:30 显示英文协议错误 + `request_id`。
- 处置：`ModelException` 拆「用户文案 / 诊断原文」；UI 只显示用户文案；错误记录保存脱敏诊断；提供「复制诊断信息」。
- 附带：`parseStreamChunk()` 300-320 对流中 error 事件静默忽略（`choices` 缺失即返回空），会出现「空回复但显示成功」。

**P0-7｜Agent 执行没有服务层开关**
- 可触发路径：`ChatScreen` 232-244 wrench 按钮 → `toggleAgentMode()` 334-345 → `generate()` 396-400 → `AgentRunner.run()`。
- 另有 `AgentEditScreen` 权限授予、`ProfileScreen` Agent 运行记录、`AgentRunsScreen` 路由。
- 处置：全局 `AppFeatureFlags.agentExecutionEnabled = false`；UI 入口移除；`AgentRunner.run()` 入口直接拒绝；普通聊天不再查询 Agent 授权；旧 `agentMode=true` 忽略；不删表、不删旧授权与运行记录。

**P0-8｜双状态事实源**
- `ChatUiState` 同时有 `isStreaming` 与 `composerState`；`generate()` 453-460 只写 `isStreaming=true`；`stopGenerating` 296-307 只写 `composerState`，不写 `isStreaming`；C 页面用 `isStreaming` 判断，A 页面用 `composerState`。
- 处置：`composerState` 为唯一事实源，`isStreaming` 变为派生属性；所有写入口统一。

## 4. 用户点名项专项

### 4.1 删除（暂停）Agent 功能

**现状**：
- 服务层：`AgentRunner.run()` 26-93 是真实工具执行闭环，`AgentToolRegistry` 提供工具，`AgentManager` 管授权。
- UI：聊天页 wrench、`toggleAgentMode`、`AgentEditScreen` 312-330 授权区、`ProfileScreen` 116-121 运行记录、`AgentRunsScreen` 路由。
- 数据：`AgentEntity`、`AgentRunEntity`、consent、`agent_disclaimer.txt`、备份类别 `agent`。

**处置**：
1. 新增 `AppFeatureFlags`（`agentExecutionEnabled = false`），先于一切执行判断；
2. 移除聊天页 Agent 按钮与 `agentMode` 状态；
3. `AgentRunner.run()` 在开关关闭时直接抛「Agent 执行已暂停」，即使旧授权/旧 `agentMode` 存在；
4. 普通聊天不再查询 `agentManager.isAuthorized()`；
5. 隐藏 Agent 权限、运行记录、免责入口；保留错误记录；
6. 不删表、不清理旧数据，备份仍可读写。

### 4.2 删除 DeepSeek 式独立 UI

**现状**：`ui_style` 设置、`ChatScreen` 分支（160-211）、`DeepSeekChat.kt` 642 行、外观页选项、我的页文案「微信式 / DeepSeek 式」、`视觉规范-DeepSeek风格.md`。

**处置**：
1. 删除 `DeepSeekChat.kt`、C 专属 Composer/PillButton/操作栏；
2. 删除外观页「DeepSeek 式」选项，保留「微信式」说明或直接不展示无意义选择；
3. `ui_style=deepseek → wechat` 幂等迁移（启动时、读取时双保险）；
4. 保留 DeepSeek provider 适配、web search、TTS、reasoning 参数；
5. 清理 C 专属 token（`DS*`）与文档；`视觉规范-DeepSeek风格.md` 移入 archive 并标注不再现行。

### 4.3 官方 TTS 不生效（用户重点）

**代码事实**：
- `TtsService.speak()` 22-34：`tts_provider != "deepseek"` → `false`；按 `baseUrl.contains("deepseek")` 找 provider；`SecretStore.decrypt` 为空 → `false`；合成失败 `runCatching` 吞掉 → `false`。
- `playWav()` 36-52：`MediaPlayer.setDataSource + prepare() + start()` 在调用线程（主线程）同步执行；异常只 `Logger.w`，**不返回失败**。
- `speak()` 32-33：`playWav(bytes)` 后直接 `return true`。
- `DeepSeekTts.synthesize()` 28-35：`text.take(MAX_CHARS=10000)`。

**根因判断（按影响排序）**：
1. **播放失败仍返回 true**：`playWav` 抛异常被吞，`speak` 返回 true → UI 不回退系统 TTS、无任何提示 → 用户感知「不生效、没声音」。
2. **配置缺失静默**：未添加 DeepSeek 服务商 / Key 解密为空 / baseUrl 不含 deepseek 时直接返回 false，回退系统 TTS，没有提示「为什么没用云端」。
3. **主线程同步 prepare**：长音频阻塞 UI，极端情况 ANR。
4. **长中文文本截断与计费规则不一致**：API 中文按 2 个计费字符，10000 字符上限对应约 5000 汉字；当前按 Java 字符数截断，长中文消息可能 400（Content Exists Risk / 超限）。
5. **WAV 流式头**：服务端边合成边返回，若 RIFF/data size 为 0 或占位值，部分 MediaPlayer 实现无法播放。

**处置**：
- `playWav` 返回 Boolean，`prepareAsync` + `onPrepared/onError`，失败返回 false；
- `speak` 返回结构化结果（成功/未配置/合成失败/播放失败），UI 据此回退系统 TTS 并给出一次轻提示（例如「云端朗读不可用，已切换系统朗读」）；
- 设置页 TTS 开关旁显示配置状态（DeepSeek 服务商/Key 是否就绪）；
- 按计费字符截断（中文 2、其他 1，上限 10000）；
- WAV 头修正（size=0/0xFFFFFFFF 时按实际字节重写 RIFF/data 长度）；
- 播放失败记录脱敏日志，不抛给用户；
- 验证：本环境无真实 DeepSeek Key 与音频输出，**真机听感 = NOT RUN**；代码级与单元级（WAV 头、截断、状态映射）可测。
