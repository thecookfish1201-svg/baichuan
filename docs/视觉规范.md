> 版本：v0.1 · 2026-11-07
> 编写：鲸鱼娘（美术与视觉协作）
> 适用范围：原生 Compose（Material 3）实现、单 HTML 演示页、文档与商店素材。

## 0. 前置约定

1. 三种 UI 风格：
   - **风格 A：微信式扁平**（默认）——灰色页面、白色列表、小圆角、高密度。
   - **风格 B：微信式液态玻璃**——A 的悬浮层绘制变体（底栏、顶栏、输入栏、弹窗），布局、色彩 token、字号与 A 完全一致，可随时关闭。
   - **风格 C：DeepSeek 式**——白/近黑单层、大留白、大圆角，默认不显示头像与名称。
2. 两套明暗主题：浅色 / 深色，跟随系统，允许手动覆盖。
3. 风格与主题相互独立，六种组合（三风格 × 两主题）都必须完整可用；液态玻璃在深色主题下按第 6 章换用深色配方。
4. 全项目只用一套图标语言、一套字号阶梯、一套间距栅格；风格差异体现在**结构密度、圆角、容器与背景**，不体现在字体和图标库里。
5. 不使用 Emoji 作为 UI 图标；文案简洁自然，不用营销腔。

## 1. 设计原则

1. **信息优先**：列表密度和消息阅读体验优先于装饰。任何视觉效果必须能一键关闭。
2. **一套中性灰，一个品牌色**：强调色只用于选中、链接、主按钮和未读提示，单屏强调色面积不超过 10%。
3. **结构学微信，气质归百川**：沿用微信的分组列表、行高、左右留白和头像位置，但不复制微信绿、微信气泡绿与微信图标形状。
4. **深浅同构**：同一组语义 token 对应浅色、深色两套值，不允许某个界面只做一套。
5. **一定可降级**：液态玻璃、模糊、动效都必须有静态替代版本，降级只改绘制，不改布局尺寸。

### 2.5 微信式与 DeepSeek 式的重点差异

| 维度 | 微信式扁平 | DeepSeek 式 |
|---|---|---|
| 背景 | 灰色页面 + 白色列表/卡片，靠层级分区 | 纯白/近黑单层，无卡片分区 |
| 顶栏 | 与页面同色，居中标题 + 右侧两个图标 | 白底，左侧菜单/折叠，右侧功能图标 |
| 头像与名称 | 永远显示 | 默认隐藏，消息只靠对齐区分 |
| 消息容器 | 有气泡，用户蓝底白字、智能体白底 | 用户浅灰底右侧、智能体无底色 |
| 分割线 | 列表内 1dp 细线，左缩进 | 尽量不用线，用留白分组 |
| 圆角 | 小圆角 6–10dp，偏方 | 大圆角 16–28dp，偏胶囊 |
| 密度 | 高（行高 72dp、16sp 正文） | 低（留白 20dp、17sp 正文、行高 1.7） |
| 强调 | 选中项、角标、主按钮 | 胶囊按钮、主按钮、链接 |
| 聊天背景 | 默认纯色，可设独立背景图 | 默认纯色或渐变，可设独立背景图 |

**风格 B（微信式液态玻璃）与风格 A 的唯一区别**：把底栏、顶栏、输入栏、操作面板、弹窗的底色由纯色换成玻璃绘制（模糊 + 半透明 + 高光描边），其余颜色映射、圆角、字号、间距全部继承微信式扁平。因此实现上它是 A 的一个绘制开关，不是第三套组件体系；关闭开关即回到 A，不需要重排布局。

三种风格**共用**：品牌主色体系、语义色、图标库、字号阶梯、48dp 触控热区、深色逻辑。切换风格只替换颜色映射、圆角与容器参数，不替换组件结构；风格 B 只替换悬浮层绘制。

### 2.6 用色规则

1. 背景图上的文字：必须先铺 `scrim`（浅色图 24%–32% 黑，深色图 40%–48% 黑），再验证 4.5:1。
2. 深色模式不使用大面积纯黑 `#000000` / 纯白 `#FFFFFF`；深色页面底用 `#0F1115`，卡片用 `#191C22`。
3. 大面积渐变只允许出现在「聊天独立背景」与「启动页」，UI 容器一律纯色或玻璃。
4. 头像、Logo、插件图标可以是彩色；界面图标必须单色（`currentColor` 语义）。
5. 未读角标与错误红点视觉相似但含义不同：未读用 `unread`，错误用 `danger` + `error` 图标，不可只靠颜色区分。

## 3. 字体与字号层级

### 3.1 字体族

- 中文：系统默认无衬线（Noto Sans CJK / 思源黑体 / 厂商字体），**不打包中文字体**，避免包体与授权成本。
- 西文与数字：Compose 默认 Roboto；版本号、Token 用量、耗时等数字可用 `Roboto Mono`（等宽），保持对齐。
- 字重只用三档：Regular 400、Medium 500、SemiBold 600（仅标题与数字强调）。
- 不启用自动字号缩放以外的自定义字体族；系统字号放大到 1.3 倍时布局不得截断。

### 3.2 层级表

| Token | 字号 | 行高 | 字重 | 用途 |
|---|---|---|---|---|
| `display` | 28sp | 36sp（1.3×） | Medium | 空状态大标题、引导页 |
| `title_lg` | 22sp | 30sp（1.35×） | Medium | 页面大标题、「我的」页昵称 |
| `title` | 17sp | 22sp（1.3×） | Medium | 顶栏标题、对话框标题（微信式） |
| `title_ds` | 20sp | 28sp（1.4×） | Medium | DeepSeek 式欢迎语、会话标题 |
| `section` | 14sp | 20sp（1.4×） | Medium | 分组标题、设置分组名 |
| `body` | 16sp | 26sp（1.6×） | Regular | 正文、消息气泡、列表主文字 |
| `body_compact` | 16sp | 22sp（1.35×） | Regular | 微信式列表主文字（单行截断） |
| `body_long` | 15sp | 26sp（1.7×） | Regular | 长消息、说明段落、免责声明 |
| `body_ds` | 17sp | 29sp（1.7×） | Regular | DeepSeek 式消息正文 |
| `secondary` | 13sp | 18sp（1.4×） | Regular | 列表摘要、辅助说明 |
| `label` | 12sp | 16sp（1.33×） | Regular | 时间戳、底栏标签、字段说明 |
| `badge` | 10sp | 12sp（1.2×） | Medium | 未读数字、角标 |
| `button` | 15sp | 18sp（1.2×） | Medium | 主次按钮 |

规则：

1. 正文最小 13sp；12sp 只用于时间戳、标签等非关键信息；10sp 只用于角标。
2. 行高按上表执行，不用默认行高；中文正文行高不低于 1.5×。
3. 同一页面最多使用 4 个层级；列表主副文字固定 16/13。
4. 消息气泡内的代码块用 `mono`，左右内边距与气泡一致，横向可滚动，不折行破坏缩进。

## 4. 间距与圆角规范

### 4.1 基础栅格

- 全部间距取 **4dp 栅格**：2 / 4 / 8 / 12 / 16 / 20 / 24 / 32 / 48。
- 页面左右边距：微信式 16dp；DeepSeek 式 20dp。
- 同组元素间距 8dp，跨组 16dp，跨区块 24–32dp。
- 最小可点区域 48×48dp，图标按钮视觉尺寸可小，热区不可小。

| 大卡片 / 弹窗 | 12dp | 20dp |
| 消息气泡 | 6dp（贴头像侧上角 2dp） | 20dp（贴边侧 4dp） |
| 输入栏 | 8dp | 26dp（胶囊） |
| 搜索框 | 6dp | 20dp |

### 4.4 安全区与适配

- 状态栏、导航栏、手势区全部使用 `WindowInsets`，不写死 padding。
- 键盘弹出时，输入栏上移，消息列表滚动到底部；键盘高度变化不改变气泡宽度。
- 横屏与折叠屏：列表最大内容宽度 600dp 居中，聊天气泡最大宽度不变。
- 系统字号放大 1.3 倍时：列表项高度可自适应，不允许文字被裁切。

## 5. 图标规范

### 5.1 选型结论：Material Symbols（Rounded）

**不选 Lucide。** 理由：

1. 工程已确定 Kotlin + Compose + Material 3（见《计划.md》），Material Symbols 与 M3 的 24dp 画布、2dp 线宽、视觉重心同源，和 M3 组件的默认图标混用不突兀；Lucide 端点更细锐，和微信式扁平列表、M3 控件放在一起会显轻。
2. Symbols 提供 Outlined / Filled / Rounded / Sharp 多种风格与可变字重，「Filled 表示选中」可以同时满足两套界面（微信式、DeepSeek 式）的底部导航。
3. 语义覆盖完整：`extension`（插件）、`hub`（MCP）、`memory`（记忆）、`backup`（备份）、`shield`（权限）、`psychology`（思考深度）等系统语义图标齐全；Lucide 部分需自绘，破坏一致性。
4. Apache License 2.0，可商用、可修改、可随开源项目分发，符合本项目开源定位。
5. 可按需子集化：只引入本项目用到的 40–60 个图标，转成 VectorDrawable / ImageVector，包体与构建内存可控；单 HTML 演示页复用同一批 SVG 源文件，三端图形完全一致。

实施建议：

- 从 Google Fonts 图标站下载所需 SVG（Rounded 变体），逐个转为矢量资源，统一命名 `ic_<名称>`。

- 若后续确需动态图标名（插件提供图标），再评估子集化 TTF + ligature 方案；核心界面坚持静态矢量资源。

## 6. 液态玻璃风格的可实现性建议

### 6.1 配方

一层「玻璃」由四部分组成，缺一不可，否则会变成半透明脏色块：

1. **背景模糊**：模糊半径 20–24dp（浅色）/ 20–24dp（深色）。
2. **半透明填充**：浅色 `#FFFFFF` 68%–78%；深色 `#16191F` 62%–72%。
3. **高光描边**：1dp，浅色 `#FFFFFF` 55%–65%，深色 `#FFFFFF` 10%–14%。
4. **极轻阴影**：浅色 `0 8dp 24dp rgba(0,0,0,0.08)`；深色不投影，用描边区分。

适用范围：悬浮层（底部导航、输入栏、顶栏、操作面板、弹窗）。**不适用**于列表卡片、消息气泡、设置分组——这些保持扁平，否则整屏糊成一片。

### 6.2 Compose 中的实现要点与限制

- `Modifier.blur(radius)` 依赖 `RenderEffect`，仅在 **Android 12（API 31）及以上**生效；API 26–30 上不模糊，必须走降级分支。
- `Modifier.blur` 模糊的是**自身绘制内容**，不是背后的页面。要做出「透出背景」的毛玻璃，需要把背景内容绘制到离屏层再模糊，例如：`drawWithCache` 中捕获背景 → `BlurEffect` → 按玻璃形状裁剪；或使用成熟的 Haze 类库。直接给玻璃层加 `blur` 只会模糊半透明色块本身，得到一片灰雾。
- 每个 `RenderEffect` 都是 GPU 采样，成本随面积线性增长。禁止全屏常驻模糊，禁止在 `LazyColumn` 的每一项上使用模糊。
- 动效：玻璃层出现/消失用 200ms 透明度过渡；不要对模糊半径做动画（每帧重建 RenderEffect，低端机必卡）。

示意片段（仅说明组合方式，不是工程代码，落地以实现为准）：

```kotlin
val glassModifier = if (blurAvailable) Modifier
    .graphicsLayer { renderEffect = BlurEffect(24f, 24f, TileMode.Clamp).asComposeRenderEffect() }
    .clip(RoundedCornerShape(16.dp))
    .background(Color.White.copy(alpha = 0.72f))
    .border(1.dp, Color.White.copy(alpha = 0.55f), RoundedCornerShape(16.dp))
else Modifier
    .background(Color(0xFFF7F7F7))
    .border(1.dp, Color(0xFFE5E5E5), RoundedCornerShape(16.dp))
```

（注：上面的 `blur` 作用于玻璃层自身时只得到半透明色块，真正的背景模糊需按上一条做离屏捕获。）

### 6.3 三级降级策略

| 级别 | 触发条件 | 绘制方式 | 预期 |
|---|---|---|---|
| L1 完整液态玻璃 | API ≥ 31、非低内存设备、用户开启 | 背景模糊 20–24dp + 半透明填充 + 高光描边 | 底栏、顶栏、输入栏、弹窗呈现玻璃质感 |
| L2 磨砂 | API ≥ 31 但判定为中端机，或帧率不达标 | 模糊降到 10–12dp，仅底栏与输入栏启用；其余用 88%–94% 不透明纯色 + 描边 | 保留一点通透感，明显降低 GPU 开销 |
| L3 扁平 | API < 31、低内存设备、省电模式、用户手动关闭 | 纯色卡片，无模糊、无半透明叠加，只保留圆角、1dp 分割线与描边 | 与微信式扁平完全一致，视觉不塌 |

### 6.4 设备判定与开关

- 系统版本：`Build.VERSION.SDK_INT >= Build.VERSION_CODES.S`。
- 低内存：`ActivityManager.isLowRamDevice`。
- 省电：`PowerManager.isPowerSaveMode`。
- 可选的自适应降级：连续 3 帧绘制超过 32ms 时自动从 L1 降到 L2，并在设置页提示「已为流畅度降低模糊」。
- 设置项：外观 → 液态玻璃（自动 / 开启 / 关闭），默认「自动」；低端机默认落到 L3；切换即时生效，不需要重启。
- 降级只改绘制，**不改任何尺寸与间距**，避免切换时布局跳动。
- 只在微信式风格下提供液态玻璃；DeepSeek 风格保持纯白极简，不叠加玻璃。

### 6.5 性能红线

1. 玻璃层总面积不超过屏幕的 25%，同屏玻璃层不超过 3 层。
2. 列表滚动、键盘弹出动画期间，暂停背景模糊的逐帧更新。
3. 低端机不做滚动视差、不做动态模糊半径。
4. 玻璃层不使用 `alpha` 动画叠加模糊，统一用颜色过渡。
5. 若启用第三方模糊库，必须固定版本并评估包体与构建内存（本机构建内存紧张）。

## 8. Logo 与头像占位规范

### 8.1 Logo 占位

正式 Logo 由项目发起者设计，本规范只约定占位与尺寸，不代替设计。

| 用途 | 尺寸 | 格式 | 说明 |
|---|---|---|---|
| 自适应图标前景/背景 | 108×108dp（xxxhdpi 432×432px） | 矢量优先 | 内容限制在直径 66dp 的圆内；外圈 18dp 由系统裁切，不要自带圆角外框 |
| 主图标 | 1024×1024px | SVG + PNG | 文档、README、商店主图 |
| 商店图标 | 512×512px | PNG（32 位） | 不透明背景 |
| 启动页图标 | 288×288px | 矢量/PNG | 背景色取 `#2F5BEA` 或 `#FFFFFF` |
| 单色图标（monochrome） | 108×108dp | 矢量单色 | 用于 Android 13+ 主题图标 |
| 关于页横版组合 | 高度 32dp + 名称 12sp | 矢量 | Logo 与「百川」水平间距 8dp |

占位方案（发起者提供正式 Logo 前使用）：

- 底色 `#2F5BEA`，中央白色几何水波纹或「百」字（思源黑体 Medium，字高约 52% 画布），不使用渐变和额外投影。
- 同时提供深色版（深底白纹）与单色版；占位与正式版必须同尺寸、同安全区，替换时不改布局。
- 启动页用「品牌色底 + 白色 Logo」，避免白底白图标。

Logo 禁止：拉伸变形、加投影/描边、自行加圆角外框、小于 24dp 显示、在彩色照片上直接叠加（需加底板或描边）。

### 8.2 头像占位

| 场景 | 尺寸 | 微信式形状 | DeepSeek 式形状 |
|---|---|---|---|
| 会话列表 | 48dp | 6dp 圆角方形 | 圆形 |
| 聊天气泡 | 40dp | 6dp 圆角方形 | 默认隐藏（开启后 36dp 圆形） |
| 智能体详情 | 56dp | 8dp 圆角方形 | 圆形 |
| 编辑页预览 | 80dp | 10dp 圆角方形 | 圆形 |
| 通知小图标 | 24dp | 单色剪影 | 单色剪影 |

默认头像规则：

1. 取名称首字（中文）或首字母（西文），白字，居中，字号约头像边长 40%。
2. 背景色由名称哈希稳定映射到 8 色低饱和色板（`#2F5BEA`、`#3A8F6B`、`#B07A2E`、`#8A5AA8`、`#B0506A`、`#4A7FA8`、`#6B7A8F`、`#A06A3A`），同一名称永远同色，不用随机色。
3. 未设置头像时不得使用 Emoji、不得使用网络图片占位。
4. 加载中：`#E3E5E8`（深色 `#2A2C30`）底 + 24% 不透明度的 `person` 图标；加载失败回退默认首字头像。
5. 未读红点位于头像右上角：无数字直径 8dp；有数字最小直径 18dp，数字 10sp，超过 99 显示「99+」，偏移量 -2dp。
6. 头像叠在浅色背景图上时加 1dp `rgba(0,0,0,0.08)` 描边，保证边界清晰。
7. 用户头像与智能体头像规则一致；机器人/智能体无头像时默认用 `smart_toy` 图标 + 灰色底，不用真人照片。

### 8.3 聊天独立背景

- 背景图需支持纯色、渐变、图片三种；图片默认 `ContentScale.Crop` 居中。
- 背景图上的气泡必须提高不透明度：浅色主题智能体气泡不低于 92% 白，深色不低于 88% 深底；用户气泡保持不变。
- 背景图整体叠加 12%–24% 的 scrim（深色主题 24%–36%），保证文字 4.5:1。
- 背景图选择页提供实时预览，预览中显示两条示例消息，可直接判断可读性。

### A.2 主题映射问题

1. `Theme.kt` 中浅色 `primary = #07C160`、`onPrimary = White`：对比约 2.4:1，主按钮文字不可读。若保留绿，`onPrimary` 改为深墨绿 `#06301A`（约 6:1），或主按钮底色改为深绿/川蓝。
2. 深色 `primary` 仍为 `#07C160`，在 `#111111` 上作为图标与选中态可读（约 7.9:1），可保留；但深色主按钮仍受上一条约束。
3. 未启用 `dynamicColor`，正确：三套风格需要稳定品牌色，不应让 Android 12+ 动态取色改写界面。
4. 色板缺少 `scrim`、玻璃填充/描边、`unread`、`success`、`warning`、`ds_*` 系列 token；风格 C 与液态玻璃落地前需补齐。

### A.4 图标资源差异

现有 `ic_tab_chat.xml`、`ic_tab_manage.xml`、`ic_tab_discover.xml`、`ic_tab_profile.xml` 均为 24×24dp、单色 Filled 路径，来自传统 Material Icons，与规范选定的 Material Symbols（Rounded）不是同一套字形。建议：

1. 按第 5.3 节换成 Symbols Rounded 对应图标（`chat_bubble` / `dashboard` / `explore` / `person`），保留 `ic_tab_*` 文件名，避免改调用点。
2. 补齐 Outlined 与 Filled 两态：未选中 Outlined、选中 Filled；若只保留一套，则用 `tint` 区分选中，但至少保证四个图标的线宽、圆润度一致。
3. 新增的图标统一 `ic_*` 前缀，集中在 `res/drawable/`，不散落。
4. 明确禁止继续用 Filled 传统图标与 Symbols 混排（四个底栏图标必须同源）。

### A.5 落地优先级

| 优先级 | 事项 | 原因 |
|---|---|---|
| P0 | 主按钮 `onPrimary` 对比度；`bg` 与 `surfaceVariant` 互换；底栏图标同源 | 影响可读性与界面一致性，改动小 |
