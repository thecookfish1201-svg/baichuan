## 1. 项目信息

- 项目名称：百川（暂定）
- 发起主体：同舟未济

- 原则：核心聊天独立运行；插件只扩展不替代；稳定、兼容、数据安全优先；用户拥有自己的配置与数据；不自营模型 API 与云服务器；第一版重点建设基础软件与插件框架

## 2. 运行环境评估（本机容器）

实测于 2026-11-07，容器运行在用户的 Android 设备内：

| 项 | 结论 |
|---|---|
| 系统 | Ubuntu 24.04.3 LTS，内核 5.15.180-android13，`aarch64` |
| CPU / 内存 | 8 核 / 11 GB 物理内存，构建时可用约 2.4–2.6 GB |
| 磁盘 | 约 47 GB 可用 |
| 已有 | Node 24.19、npm 11、pnpm 10.34、Python 3.12、git 2.43 |
| 缺失 | JDK、Android SDK、Gradle、Flutter（均需自备） |
| 网络 | npm / Maven Central / Google Maven / Gradle 官方源可达；国内镜像更快 |
| Android 运行时 | 容器可访问宿主的 `/system`（含 `/system/bin/linker64`），可运行 bionic 链接的 arm64 程序 |

已完成的关键验证：

1. **JDK 17**：Temurin 17.0.21 aarch64 已就位（`/opt/toolchain/jdk-17.0.21+9`），`java`/`javac` 正常。
2. **aapt2 arm64**：Google 官方 build-tools 的 aapt2 只有 linux-x86_64，本机无 x86 模拟层（binfmt/qemu 均不可用）。改用 Termux 移植的 arm64 `aapt2 2.20-android-16.0.0_r4`，配合宿主 bionic linker 与 Termux 运行库后 **已成功运行**。
3. **Android SDK**：cmdline-tools 下载中，随后安装 `platforms;android-35`、`build-tools;35.0.0`。
4. **最小 APK 构建（2026-11-07 14:22 完成）**：`BUILD SUCCESSFUL`，产出 `app-debug.apk`（8.3 MB，minSdk 26 / targetSdk 35，debug 签名校验通过，`aapt2 dump badging` 正常）。首次构建含依赖下载约 24 分钟，增量构建 4 分 29 秒。探针工程位于 `/tmp/probe`，仅用于验证，不进入正式工程。
5. **构建脚本**：`tools/env.sh`（环境变量）、`tools/aapt2/aapt2`（arm64 aapt2 包装）、`scripts/build.sh`（统一构建入口）。

> 结论：本机具备“原生 Android（Kotlin/Compose）工程可构建”的基础条件；但 aapt2 为社区移植版本，需要固定版本并纳入 `tools/` 管理，避免与 AGP 升级冲突。

## 3. 技术栈

### 3.1 方案对比

| 方案 | 优点 | 风险 | 结论 |
|---|---|---|---|
| **A. Kotlin + Jetpack Compose（原生）** | 与目标平台一致；后台任务、通知、TTS、文件、无障碍等系统能力最完整；性能与包体可控；长期维护成本低 | 本机构建链需 aapt2 适配（已验证可行）；Compose 编译内存需求较高 | **推荐** |
| B. Flutter | 跨平台、UI 一致性好 | 本机 arm64 Flutter 工具链较重；APK 构建同样依赖 aapt2 适配；系统能力仍需平台通道 | 备选 |
| C. Web + Capacitor 壳 | 与“单 HTML 测试文件”天然共用代码；开发快 | 原生能力依赖插件桥；长期性能与后台能力弱，不符合“稳定性优先” | 仅作演示层参考 |

### 3.2 拟采用组合（待发起者确认）

- 语言：Kotlin 2.x
- UI：Jetpack Compose + Material 3，单 Activity
- 架构：MVVM + 单向数据流（StateFlow），模块化（`:app` / `:core:*` / `:feature:*`）
- 本地存储：Room（SQLite）+ 事务；附件存应用私有目录
- 凭据安全：Android Keystore + EncryptedSharedPreferences（API Key 不明文落库/落日志）
- 网络：OkHttp + kotlinx.serialization；SSE 流式解析
- 后台：WorkManager（自动消息）+ 前台服务 + 通知渠道
- 构建：Gradle 8.x + AGP 8.x + JDK 17
- 最低系统：Android 8.0（API 26），目标 API 35

## 5. 数据库设计 v1（拟）

Room 单一数据库 `baichuan.db`，启用 WAL 与外键。

### 核心表

| 表 | 关键字段 | 说明 |
|---|---|---|
| `agents` | id, name, avatar_uri, persona, system_prompt, background_uri, model_ref, memory_enabled, blocked, created_at, updated_at | 智能体；删除为软删除 |
| `conversations` | id, agent_id, title, background_uri, created_at, updated_at, archived | 会话 |
| `messages` | id, conversation_id, role, content, content_type, parent_id, status, error_id, created_at | `parent_id` 形成消息树，支持编辑/重新生成分支 |
| `attachments` | id, message_id, type, uri, mime, size, name | 图片/文件附件 |
| `providers` | id, name, base_url, protocol, key_ref, extra_json, created_at | 服务商；API Key 仅存引用 |
| `models` | id, provider_id, model_name, display_name, capabilities_json, is_default | 模型与能力标记 |
| `aux_bindings` | id, capability, provider_id, model_id, params_json | 视觉/TTS/压缩/搜索等辅助能力绑定 |
| `memories` | id, agent_id, content, pinned, created_at, updated_at | 记忆条目 |
| `error_events` | id, agent_id, conversation_id, message_id, code, summary, detail, created_at, deleted_at | 错误事件（脱敏） |
| `scheduled_messages` | id, agent_id, mode, content, window_start, window_end, interval_min, interval_max, enabled | 主动消息 |
| `plugins` | id, plugin_id, name, author, version, api_version, type, permissions_json, state, installed_at | 未济插件 |
| `plugin_data` | id, plugin_id, key, value | 插件独立数据空间 |
| `settings` | key, value | 全局设置 |

### 设计约定

- 消息时间存为独立元数据列，**不拼接进提示词前缀**，避免破坏上下文缓存命中。
- 删除智能体 / 删除聊天记录 / 删除插件数据是三个独立操作，互不隐式级联。
- API Key、密码、Token 一律不进普通日志与普通备份；备份中仅保存加密引用或用户口令加密块。
- 错误事件保留“恢复”能力（软删除标记 `deleted_at`）。

## 6. 模块依赖关系（拟）

```
ui ──> chat / agent / memory / search / backup / plugin / mcp / agentlab
                    │
                    ├──> model（统一适配层）
                    │        ├──> openai-compatible
                    │        ├──> op（待定义）
                    │        └──> custom
                    └──> core（db / net / security / prefs）
```

约束：

- `core` 不依赖任何 feature；feature 之间只通过接口（DI）通信。
- 模型适配层不写死任何供应商参数；聊天核心不感知具体供应商。
- 插件只能通过 `plugin` 暴露的受限接口访问资源，不能直接调用 `core` 内部实现。
- 插件异常被 `plugin` 运行时捕获并隔离，不得影响聊天主链路。

## 8.2 已知问题与技术风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 构建内存仅约 2.5 GB | Gradle/Kotlin 编译可能 OOM | 已限制 `-Xmx1536m`、关闭并行；实测通过 |
| 首次/全量构建慢（依赖下载 + arm64 D8） | 迭代变慢 | 依赖已缓存；增量构建约 4–5 分钟，可接受 |
| aapt2 为 Termux 移植版 | 与 AGP 版本不完全对齐 | 固定版本并在 `tools/` 内管理；`android.aapt2FromMavenOverride` 指向本地 |
| 无 x86 模拟层、无本地模拟器 | 无法运行 Android 模拟器做 UI 自动化 | 单元测试 + 真机安装验证（通过设备通道） |
| 无正式真机自动化测试设施 | 兼容性验证成本高 | 每阶段构建 APK，交发起者真机验收 |
| Android 后台调度限制 | 主动消息时间不精确 | 采用 WorkManager + 前台服务，明确提示“不承诺精准时间” |
| 代码型插件沙箱未评估 | 安全风险 | 第一版只做配置型插件 + 协议；代码型插件另行评估 |
| Compose 液态玻璃模糊性能 | 低端机卡顿 | 提供降级路径（无模糊的扁平风格） |

## 9. 决策与待确认问题

### 已确认（2026-11-07 发起者拍板）

1. 技术栈：Kotlin 2.x + Jetpack Compose（原生），不使用 Flutter / Web 壳。
2. 图标：使用开源矢量图标库（Material 图标体系），不允许 Emoji 充当 UI 图标。
3. OP 协议：第一版只预留协议枚举与接口位，配置可填但标记不可用，不进入阶段二验收。
4. 验收：每个阶段由发起者亲自在本机真机验收，开发侧只负责构建与自测。

### 待确认（阶段二动工前，哦鲸鲸评审提出）

1. **消息分支定稿**：切换分支后重新生成，是新建兄弟节点还是覆盖原节点？当前默认实现为「新建兄弟节点，保留旧分支，activeLeafMessageId 指向当前路径末端」。
2. **会话模型**：微信式与 DeepSeek 式是否共用「智能体下多会话」结构？当前默认：共用同一套表，微信式默认只用一个会话并隐藏会话列表，DeepSeek 式展示会话列表。
3. **文件策略**：附件、头像、聊天背景统一复制进应用私有目录（相对路径存储），备份携带附件；导入时按相对路径重映射。
4. **自动消息后台模型**：WorkManager + 前台服务；应用被杀或重启后按「不补发过期消息、只安排下一次」处理；通知权限被拒时降级为静默不发送并提示。
5. **阶段二验收 API**：由发起者提供测试 Key 与网络环境；无法联网时以「本地 Mock 适配器」完成降级验收。
